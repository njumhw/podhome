# 数据库连接稳定性修复方案

## 问题诊断

1. **现象**：
   - 重启服务器后正常，但很快又出现问题
   - API返回HTML错误页面而不是JSON（`unexpected token '<'`）
   - 503错误：数据库连接失败
   - hot/top播客列表无法加载

2. **根本原因**：
   - Supabase数据库连接不稳定
   - 连接池可能耗尽（当前20个连接）
   - `hot`查询使用了`_count: { select: { likes: true } }`，这会触发JOIN查询，非常慢且占用连接
   - 没有连接健康检查和自动恢复机制

## 已实施的修复

### 1. 确保所有API返回JSON（已修复）
- ✅ `/api/public/list` 添加了完整的错误处理
- ✅ `/api/auth/login` 添加了数据库错误处理
- ✅ 所有错误都返回JSON，不再返回HTML

### 2. 数据库连接优化（已修复）
- ✅ 连接池大小：10 → 20
- ✅ 连接超时：20秒 → 60秒
- ✅ 添加了健康检查和自动重连机制

### 3. 查询超时保护（已修复）
- ✅ 添加了`withQueryTimeout`工具函数
- ✅ hot查询添加了15秒超时
- ✅ 查询失败时返回空数组而不是崩溃

## 还需要优化的地方

### 1. hot查询性能问题（关键！）

**当前问题**：
```typescript
_count: { select: { likes: true } }  // 这会触发JOIN查询，非常慢
```

**建议优化方案**：
1. **方案A（推荐）**：使用`hot_all`缓存结果，然后过滤30天内的
2. **方案B**：先查询播客，再批量查询点赞数（使用`groupBy`）
3. **方案C**：在播客表中添加`likeCount`字段，定期更新（需要迁移）

### 2. 连接池监控

建议添加：
- 连接池使用情况监控
- 慢查询日志
- 连接失败告警

### 3. 缓存策略优化

当前：
- `hot`类型：5分钟缓存
- `latest`类型：30秒缓存

建议：
- 增加`hot`类型缓存时间到10分钟
- 添加过期缓存降级（已实现）

## 临时解决方案

如果问题持续出现，可以：

1. **增加PM2自动重启**：
   ```bash
   pm2 start ecosystem.config.js --max-restarts 10 --min-uptime 1000
   ```

2. **定期重启应用**（cron job）：
   ```bash
   # 每天凌晨3点重启
   0 3 * * * pm2 restart podroom
   ```

3. **监控数据库连接**：
   - 在Supabase控制台查看连接数
   - 如果连接数接近上限，考虑升级Supabase计划

## 长期解决方案

1. **使用Redis缓存**：
   - 缓存热门播客列表
   - 减少数据库查询压力

2. **优化数据库查询**：
   - 添加索引（`updatedAt`, `status`, `topicId`）
   - 使用物化视图存储热门播客

3. **分离读写**：
   - 使用只读副本处理查询
   - 主库只处理写入

4. **连接池管理**：
   - 使用PgBouncer等连接池工具
   - 更好的连接复用
