# UI 调试检查清单

## 当 UI 修改没有生效时，按以下步骤排查：

### 1. 确认问题位置
- [ ] 在浏览器 DevTools 中检查实际渲染的 HTML 结构
- [ ] 确认元素的实际标签类型（`<button>` vs `<a>` vs `<div>`）
- [ ] 确认元素的实际 className 和样式
- [ ] 截图或记录 DevTools 中显示的信息

### 2. 搜索整个代码库
- [ ] 使用 `grep` 搜索相关的文本内容（如按钮文字）
- [ ] 使用 `grep` 搜索相关的 className
- [ ] 使用 `codebase_search` 进行语义搜索
- [ ] 检查是否有多个组件/文件在渲染相同的 UI

### 3. 确认修改位置
- [ ] 对比 DevTools 中的 HTML 和代码中的组件
- [ ] 确认是否所有相关位置都已修改
- [ ] 确认是否有缓存问题（浏览器缓存、Next.js 构建缓存）

### 4. 修改和验证
- [ ] 修改所有相关位置
- [ ] 检查 CSS 规则的选择器是否匹配实际元素
- [ ] 硬刷新浏览器（Cmd+Shift+R）验证
- [ ] 清除 Next.js 缓存（`.next` 目录）如果必要

## 常见陷阱

1. **假设只有一个组件**：可能有内联代码、多个组件、或者条件渲染
2. **只看组件文件**：可能在其他页面文件中有内联实现
3. **忽略 DevTools**：实际渲染的 HTML 可能与代码不一致
4. **CSS 优先级问题**：可能被其他规则覆盖，需要检查计算样式

## 本次案例总结

**问题**：VisitorLimitModal 登录按钮文字颜色在白色主题下不正确

**错误**：
- 只修改了 `VisitorLimitModal.tsx`
- 忽略了 `podcast/[id]/page.tsx` 中的内联弹窗代码
- 没有先检查 DevTools 确认实际渲染的 HTML

**正确做法**：
1. 先看 DevTools，发现是 `<a>` 标签而不是 `<button>`
2. 搜索代码库，找到所有 "登录" 按钮和 "今日查看次数已用完" 文本
3. 发现有两个位置：组件和内联代码
4. 同时修改两个位置
5. 更新 CSS 规则支持 `<a>` 标签
