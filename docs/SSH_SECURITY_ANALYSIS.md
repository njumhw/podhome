## 方案对比

### 方案A：配置SSH密钥 + 禁用密码登录

#### 操作步骤

```bash
# 1. 在本地生成SSH密钥（如果还没有）
ssh-keygen -t rsa -b 4096
# 按提示操作，可以设置密码保护私钥

# 2. 将公钥复制到服务器
ssh-copy-id -p 22 root@your.server.ip
# 或手动复制：
# cat ~/.ssh/id_rsa.pub | ssh root@your.server.ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# 3. 测试密钥登录（重要！）
ssh root@your.server.ip
# 如果成功，继续下一步

# 4. 在服务器上禁用密码登录
sudo nano /etc/ssh/sshd_config
# 修改：
# PermitRootLogin prohibit-password  # 只允许密钥
# PasswordAuthentication no          # 禁用密码

# 5. 重启SSH（⚠️ 确保密钥登录正常后再执行）
sudo systemctl restart sshd
```

#### 后续登录方式

**正常情况**：
```bash
# 直接使用密钥登录（无需输入密码）
ssh root@your.server.ip
```

**如果密钥丢失**：
- ❌ **无法登录**（除非有其他方式访问服务器）
- 需要：
  1. 通过云服务商控制台（如阿里云）的VNC/远程连接
  2. 或者提前配置多个密钥
  3. 或者保留一个备用密码登录方式（不推荐）

#### 性价比分析

**成本**：
- ⏱️ 时间：10-15分钟（首次配置）
- 💰 金钱：0元
- 🧠 学习成本：低（一次性配置）

**收益**：
- ✅ **安全性大幅提升**：即使密码泄露也无法登录
- ✅ **登录更方便**：无需每次输入密码
- ✅ **防止暴力破解**：即使Fail2ban失效，也无法通过密码登录

**效果评分**：⭐⭐⭐⭐⭐ (5/5)

**推荐度**：⭐⭐⭐⭐⭐ (强烈推荐)

### 方案B：禁止root登录 + 创建普通用户

#### 操作步骤

```bash
# 1. 创建普通用户
sudo adduser admin
# 设置密码和基本信息

# 2. 添加到sudo组（获得管理员权限）
sudo usermod -aG sudo admin

# 3. 测试新用户登录
su - admin
sudo whoami  # 测试sudo权限

# 4. 编辑SSH配置
sudo nano /etc/ssh/sshd_config
# 修改：
# PermitRootLogin no  # 禁止root登录

# 5. 重启SSH
sudo systemctl restart sshd
```

#### 后续登录方式

**正常情况**：
```bash
# 使用普通用户登录
ssh admin@your.server.ip
# 输入密码

# 需要root权限时
sudo su -  # 或使用 sudo 命令
```

**如果忘记普通用户密码**：
- 可以通过云服务商控制台重置
- 或者通过其他有sudo权限的用户重置

#### 性价比分析

**成本**：
- ⏱️ 时间：5-10分钟
- 💰 金钱：0元
- 🧠 学习成本：低

**收益**：
- ✅ **降低风险**：即使普通用户被破解，还需要sudo密码
- ✅ **审计更好**：可以追踪哪个用户执行了什么操作
- ⚠️ **安全性提升有限**：仍然依赖密码强度

**效果评分**：⭐⭐⭐ (3/5)

### 方案C：更改SSH端口

#### 操作步骤


## 实际操作建议

### 如果你选择SSH密钥方案

**第一步：在本地生成密钥**
```bash
# 在本地电脑执行
ssh-keygen -t rsa -b 4096
# 按提示操作，建议设置密码保护私钥
```

**第二步：复制公钥到服务器**
```bash
# 方法1：使用ssh-copy-id（推荐）
ssh-copy-id -p 22 root@your.server.ip

# 方法2：手动复制
cat ~/.ssh/id_rsa.pub | ssh root@your.server.ip "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**第三步：测试密钥登录**
```bash
# 测试是否能无密码登录
ssh root@your.server.ip
# 如果成功（无需输入密码），继续下一步
```

**第四步：禁用密码登录**
```bash
# 在服务器上执行
sudo nano /etc/ssh/sshd_config

# 修改以下配置：
PermitRootLogin prohibit-password  # 只允许密钥
PasswordAuthentication no          # 禁用密码登录
PubkeyAuthentication yes          # 启用密钥认证

# 保存后重启SSH
sudo systemctl restart sshd

# ⚠️ 重要：保持当前SSH连接打开，测试新连接是否正常
# 在另一个终端测试：
ssh root@your.server.ip
```

**第五步：验证配置**
```bash
# 确认密码登录已禁用
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no root@your.server.ip
# 应该被拒绝

# 确认密钥登录正常
ssh root@your.server.ip
# 应该可以正常登录
```

### 如果密钥丢失的应急预案

1. **通过云服务商控制台**
   - 阿里云：ECS控制台 → 远程连接 → VNC
   - 其他云服务商类似

2. **提前配置多个密钥**
   ```bash
   # 在服务器上添加多个公钥
   cat >> ~/.ssh/authorized_keys << EOF
   ssh-rsa AAAAB3... your-other-key
   EOF
   ```

3. **保留一个备用密码登录**（不推荐，但可以作为过渡）
   ```bash
   # 在sshd_config中设置：
   Match User backup-user
       PasswordAuthentication yes
   ```
