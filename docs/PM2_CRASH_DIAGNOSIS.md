# PM2 进程崩溃诊断

## 问题现象

- `pm2 list` 显示 `podroom` 进程存在
- 但 `uptime` 只有 1-2 秒，说明进程频繁重启
- PID 不断变化，说明进程在崩溃后自动重启
- `pm2 env podroom` 失败，因为进程状态不稳定

## 诊断步骤

### 1. 查看 PM2 日志（最重要）

```bash
pm2 logs podroom --lines 50
```

这会显示应用启动时的错误信息，找出崩溃原因。

### 2. 查看错误日志

```bash
pm2 logs podroom --err --lines 50
```

### 3. 检查进程详细信息

```bash
pm2 info podroom
```

### 4. 检查启动命令

```bash
pm2 describe podroom
```

查看启动命令是否正确。

## 常见原因

1. **代码错误**：应用启动时抛出未捕获的异常
2. **依赖问题**：缺少依赖或版本不匹配
3. **环境变量**：缺少必需的环境变量
4. **端口占用**：3005 端口被占用
5. **构建失败**：生产模式需要先构建，但构建可能失败
6. **内存不足**：应用启动时内存不足

## 解决方案

根据日志中的错误信息，采取相应的修复措施。
