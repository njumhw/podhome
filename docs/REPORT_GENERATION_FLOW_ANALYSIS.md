# 播客总结生成流程分析

## 📊 处理流程决策树

```
播客链接
  ↓
ASR转写（整体处理）
  ↓
生成总结报告
  ↓
判断输入长度
  ├─ 如果 totalInputTokens > 900,000 tokens
  │   └─ → 分块处理（generateReportChunked）
  │
  └─ 如果 totalInputTokens ≤ 900,000 tokens
      ↓
      判断段落数
      ├─ 如果 segments.length ≤ 40
      │   └─ → 单轮生成（generateReportWholeFallback）
      │       ├─ 成功 → 返回总结
      │       └─ 失败（内容审核错误等）
      │           └─ → 分块处理（generateReportChunked）
      │
      └─ 如果 segments.length > 40
          └─ → 两轮生成（大纲+填充）
              ├─ 第一轮：生成大纲
              │   └─ 成功 → 继续
              │   └─ 失败 → 回退到单轮生成
              │
              └─ 第二轮：基于大纲+ASR生成报告
                  ├─ 成功 → 返回总结+大纲
                  └─ 失败（内容审核错误等）
                      └─ → 回退到单轮生成
                          └─ 如果单轮也失败 → 分块处理
```

## 🔍 分块处理的触发条件

### 1. 输入长度超限（自动触发）
- **条件**：`totalInputTokens > 900,000 tokens`
- **计算方式**：
  - `estimatedTokens = transcript.length`（中文约1字符=1token）
  - `totalInputTokens = estimatedTokens + 10000`（提示词）
- **触发场景**：超长播客（ASR原文 > 890,000字符）
- **频率**：很少（大部分播客ASR原文在10万-20万字符）

### 2. 内容审核错误（回退触发）
- **条件**：单轮/两轮生成遇到内容审核错误
- **错误信息**：`data_inspection_failed` 或 `inappropriate content`
- **触发场景**：ASR原文或大纲触发了API的内容安全机制
- **频率**：偶尔（取决于播客内容）

### 3. API限制错误（回退触发）
- **条件**：遇到输入/限制相关的错误
- **错误信息**：包含 `input`、`limit`、`限制` 等关键词
- **触发场景**：API限流或其他限制
- **频率**：很少

## 📈 实际使用情况分析

### 正常情况（大部分播客）
- **ASR原文长度**：10万-20万字符（常见）
- **估算Token**：10万-20万 tokens
- **处理方式**：整体处理
  - 段落数 ≤ 40：单轮生成
  - 段落数 > 40：两轮生成（大纲+填充）

### 特殊情况（触发分块处理）
- **超长播客**：ASR原文 > 890,000字符（很少）
- **内容审核错误**：触发了API内容安全机制（偶尔）
- **API限制错误**：遇到限流或其他限制（很少）
