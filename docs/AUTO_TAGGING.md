# 自动主题标注系统

## 概述

自动主题标注系统通过基于规则的匹配（而非AI）为播客自动分配主题标签。系统会在播客处理完成后自动尝试标注，也支持批量标注已有播客。

## 工作原理

系统使用以下规则进行匹配：

1. **关键词匹配**：检查标题、描述、摘要、转录稿中是否包含特定关键词
2. **URL模式匹配**：根据来源URL的模式匹配（如特定平台）
3. **作者匹配**：根据播客作者名称匹配
4. **来源匹配**：根据来源平台匹配

匹配按优先级排序，第一个匹配的主题将被应用。

## 预定义规则

系统内置了以下主题的自动标注规则：

- **科技**：AI、编程、技术、互联网等关键词
- **商业**：创业、投资、商业模式等关键词
- **投资理财**：股票、基金、理财等关键词
- **文化**：历史、文学、艺术等关键词
- **教育**：学习、课程、培训等关键词
- **健康**：医疗、养生、运动等关键词
- **生活方式**：生活、习惯、时间管理等关键词
- **娱乐**：电影、音乐、游戏等关键词
- **体育**：运动、足球、篮球等关键词

## 使用方法

### 1. 自动标注（处理时）

新播客处理完成后，系统会自动尝试标注主题。如果匹配到规则，会自动分配主题。

### 2. 批量标注（命令行）

```bash
# 预览模式：查看哪些播客会被标注，但不实际更新数据库
npx tsx scripts/auto-tag-podcasts.ts --dry-run

# 实际执行：标注所有未标注的播客
npx tsx scripts/auto-tag-podcasts.ts

# 标注指定播客
npx tsx scripts/auto-tag-podcasts.ts --ids=podcast1,podcast2,podcast3
```

### 3. API 调用

#### 批量标注

```bash
POST /api/podcast/auto-tag
Content-Type: application/json
Authorization: Bearer <admin_token>

{
  "podcastIds": ["id1", "id2"],  // 可选，为空则处理所有未标注的播客
  "dryRun": false  // 是否只是预览
}
```

#### 预览单个播客

```bash
GET /api/podcast/auto-tag?podcastId=xxx
Authorization: Bearer <admin_token>
```

## 自定义规则

编辑 `src/server/topic-auto-tagger.ts` 文件中的 `AUTO_TAG_RULES` 数组来添加或修改规则：

```typescript
{
  topicName: '你的主题名称',
  priority: 10,  // 优先级，数字越大优先级越高
  rules: {
    keywords: {
      title: ['关键词1', '关键词2'],  // 标题关键词
      all: ['通用关键词'],  // 任意字段关键词
    },
    urlPatterns: [/pattern1/i, /pattern2/i],  // URL正则模式
    authors: ['作者名1', '作者名2'],  // 作者匹配
  },
}
```

**注意**：只有已审核通过的主题（`approved: true`）才会被自动标注。

## 规则优先级

1. 优先级高的规则先匹配
2. 如果多个规则匹配，选择优先级最高的
3. 如果优先级相同，选择第一个匹配的

## 注意事项

- 自动标注不会覆盖已有主题（除非明确指定播客ID）
- 自动标注失败不会影响播客的正常处理流程
- 建议定期运行批量标注来更新已有播客的主题
- 规则可以随时调整，调整后需要重新运行批量标注

## 扩展建议

未来可以考虑：

1. **基于已有播客的相似性匹配**：如果新播客与某个主题的已有播客相似，自动分配相同主题
2. **机器学习增强**：使用简单的统计方法（如TF-IDF）来改进关键词匹配
3. **用户反馈机制**：允许用户纠正自动标注结果，并用于改进规则
4. **规则管理界面**：在管理后台提供可视化的规则管理界面
