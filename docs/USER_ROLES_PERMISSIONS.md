# 用户体系权限方案

## 五档用户角色定义

### 1. Visitor（游客）
**身份标识**: 无需注册登录，基于 IP 识别

**权限范围**:
- ✅ **搜索浏览**
  - 可以搜索播客
  - 可以浏览首页（最新、最热）
  - 可以查看播客列表卡片（标题、作者、摘要预览）
  
- ⚠️ **播客详情页访问限制**
  - 每天最多查看 **3 个**播客详情页
  - 超过限制后，点击播客卡片会提示："今日查看次数已用完，请注册登录后无限浏览"
  - 计数规则：按自然日（00:00-23:59）重置
  - 计数方式：基于 IP 地址 + User-Agent 组合识别
  
- ❌ **上传功能**
  - 不能上传播客
  - 上传按钮不显示或显示为灰色，提示"请登录后上传"
  
- ❌ **点赞功能**
  - 不能点赞播客
  - 点赞按钮不显示或显示为灰色，提示"请登录后点赞"
  
- ❌ **收藏夹功能**
  - 不能查看"已点赞"标签页
  - 标签页显示但点击时提示"请登录后查看收藏"

**数据存储**:
- 访问记录存储在 `AccessLog` 表中（userId 为 null，记录 IP 和 User-Agent）
- 每日访问计数：通过 `AccessLog` 表按 IP + User-Agent + 日期聚合查询
  - 轻量化方案：每次访问时查询当天该 IP+User-Agent 的访问次数
  - 如果超过 3 次，拒绝访问并提示
  - 无需额外缓存服务，直接数据库查询即可

---

### 2. Reader（读者）
**身份标识**: 需要注册登录，**无需邀请码**，直接注册即可，角色为 `READER`

**注册方式**:
- 直接注册：邮箱 + 用户名 + 密码即可注册
- 注册后自动获得 Reader 权限
- 如需升级为 Podcaster，需要使用邀请码（见下方升级说明）

**权限范围**:
- ✅ **搜索浏览**
  - 可以搜索播客
  - 可以浏览首页（最新、最热、已点赞）
  - 可以查看所有播客列表
  
- ✅ **播客详情页访问**
  - **无限制**查看所有播客详情页
  - 可以查看完整内容（摘要、转录、评论等）
  
- ✅ **点赞功能**
  - 可以点赞/取消点赞播客
  - 点赞数据会同步到个人账户
  
- ✅ **收藏夹功能**
  - 可以查看"已点赞"标签页
  - 可以查看所有已点赞的播客列表
  - 支持分页加载
  
- ✅ **评论功能**
  - 可以评论播客
  - 可以点赞评论
  
- ❌ **上传功能**
  - 不能上传播客
  - 上传按钮不显示或显示为灰色，提示"需要 Podcaster 权限才能上传"
  
- 🔄 **升级为 Podcaster**
  - 在个人中心或上传页面，可以输入邀请码升级
  - 输入有效的 Podcaster 邀请码后，角色自动升级为 `PODCASTER`
  - 升级后立即获得上传权限（每日 1 次）

**数据存储**:
- 用户信息存储在 `User` 表（role = 'READER'）
- 点赞记录存储在 `PodcastLike` 表（userId 关联）
- 访问记录存储在 `AccessLog` 表（userId 关联）

---

### 3. Podcaster（播客创作者）
**身份标识**: 通过邀请码升级获得，角色为 `PODCASTER`，**现有所有用户默认升级到此档位**

**获得方式**:
- **方式一**：Reader 用户使用 Podcaster 邀请码升级
- **方式二**：管理员在后台直接设置为 Podcaster
- **现有用户**：所有现有的 `USER` 角色用户自动升级为 `PODCASTER`

**权限范围**:
- ✅ **Reader 的所有权限**
  - 搜索浏览
  - 无限制查看播客详情
  - 点赞功能
  - 收藏夹功能
  - 评论功能
  
- ✅ **上传功能**
  - 可以上传播客进行处理
  - **每日上传限制：1 个播客**
  - 计数规则：按自然日（00:00-23:59）重置
  - 超过限制后提示："今日上传次数已达上限（1次），请明天再试"
  - 上传按钮显示剩余次数："今日还可上传 X 次"
  
- ✅ **个人播客管理**（可选）
  - 可以查看自己上传的播客列表
  - 可以查看上传历史统计

**数据存储**:
- 用户信息存储在 `User` 表（role = 'PODCASTER'）
- 上传记录存储在 `Podcast` 表（createdById 关联）
- 每日上传计数通过 `Podcast` 表聚合查询（按 createdAt 和 createdById）

**升级说明**:
- 现有所有 `USER` 角色用户自动升级为 `PODCASTER`
- 现有所有 `ADMIN` 角色用户保持为 `ADMIN`（管理员）

---

### 4. Podcaster-VIP（VIP 播客创作者）
**身份标识**: 仅后台管理员授权，角色为 `PODCASTER_VIP`

**权限范围**:
- ✅ **Podcaster 的所有权限**
  - 搜索浏览
  - 无限制查看播客详情
  - 点赞功能
  - 收藏夹功能
  - 评论功能
  
- ✅ **无限制上传功能**
  - 可以上传播客进行处理
  - **每日上传限制：无限制**
  - 上传按钮显示："VIP 用户，无限制上传"
  
- ✅ **优先处理**（可选）
  - 上传的播客优先进入处理队列
  - 处理速度更快

**授权方式**:
- 仅管理员在后台"用户管理"页面手动授权
- 授权操作：选择用户 → 点击"设为 VIP"按钮
- 可随时取消 VIP 权限

**数据存储**:
- 用户信息存储在 `User` 表（role = 'PODCASTER_VIP'）
- 其他数据存储同 Podcaster

---

### 5. Admin（管理员）
**身份标识**: 仅你本人，角色为 `ADMIN`

**权限范围**:
- ✅ **所有功能权限**
  - 搜索浏览
  - 无限制查看播客详情
  - 点赞功能
  - 收藏夹功能
  - 评论功能
  - 无限制上传功能
  
- ✅ **后台管理权限**
  - 用户管理（查看、封禁、授权 VIP）
  - 邀请码管理（生成、查看、删除）
  - 主题审核（审核、删除主题）
  - 播客管理（查看、编辑、删除播客）
  - 任务日志查看
  - 成本监控
  - 音频配置管理
  - 提示词管理

**数据存储**:
- 用户信息存储在 `User` 表（role = 'ADMIN'）
- 特殊保护：`njumwh@163.com` 账号不可被降级或封禁

## 需要讨论的业务细节

### 1. Visitor 每日查看限制的实现
**问题**: 如何准确识别同一访客？

**方案 A（推荐）**: IP + User-Agent 组合
- 优点：实现简单，无需存储 Cookie
- 缺点：同一网络下的用户会共享限制
- 实现：在 `AccessLog` 表中记录 IP 和 User-Agent，按日期聚合查询

**方案 B**: Cookie + IP 双重验证
- 优点：更准确识别个人设备
- 缺点：需要前端 Cookie 支持，用户清除 Cookie 可绕过
- 实现：前端设置 Cookie，后端验证 Cookie + IP

**建议**: 采用方案 A，因为 Visitor 本身就是低权限角色，限制不需要太严格。

### 5. Visitor 访问计数存储方案（轻量化）
**问题**: 如何存储和查询 Visitor 的每日访问计数？

**解释**: "访问计数存储"指的是如何记录和查询 Visitor 每天查看了多少个播客详情页。

**轻量化方案（已确定）**:
- **存储方式**: 每次 Visitor 访问播客详情页时，在 `AccessLog` 表中记录一条记录
  - `userId`: null（游客无用户ID）
  - `podcastId`: 访问的播客ID
  - `createdAt`: 访问时间
  - 额外字段：记录 IP 地址和 User-Agent（可通过请求头获取）
  
- **查询方式**: 每次访问前，查询当天该 IP + User-Agent 组合的访问次数
  ```sql
  SELECT COUNT(*) FROM AccessLog 
  WHERE userId IS NULL 
    AND userIp = ? 
    AND userAgent = ?
    AND DATE(createdAt) = CURRENT_DATE
    AND podcastId IS NOT NULL
  ```
  
- **性能优化**:
  - 在 `AccessLog` 表添加索引：`(userIp, userAgent, createdAt, podcastId)`
  - 定期清理过期记录（如保留 30 天）
  - 如果访问量很大，可以考虑在内存中缓存当天的计数（但需要处理服务器重启的情况）

**优点**:
- 无需额外服务（如 Redis）
- 实现简单，直接使用现有数据库
- 数据可追溯，便于分析

**缺点**:
- 每次访问需要查询数据库（但通过索引优化，性能可接受）
- 数据量会增长（但可以通过定期清理解决）
